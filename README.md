# ipmi-web

Веб-панель для монтирования ISO-образов на серверы через BMC — без Java, без
`stunnel` и без плясок на машине администратора. Вся грязная работа
выполняется на сервере, администратору нужен только браузер.

## Зачем

На старых Supermicro в консоль ведут два пути. HTML5-консоль работает, но не
умеет пробрасывать ISO как USB — то есть не годится для установки или
восстановления ОС. Java-виджет умеет, но регулярно ломается: версия JRE,
политики безопасности, просроченные сертификаты BMC.

`ipmi-web` обходит оба: сервис держит библиотеку образов и раздаёт её по SMB, а
**BMC забирает образ сам** средствами прошивки. Java не участвует нигде,
лицензия Redfish не нужна.

## Как это работает

```
админ → браузер → ipmi-web ──(config_iso + mount_iso)──> BMC
                     │                                    │
                     └────── Samba, только чтение <────────┘
                                                    BMC сам забирает ISO
```

Монтирование прописывается в конфигурации BMC, поэтому **переживает
перезагрузки сервера** — установка ОС с её двумя-тремя ребутами не разваливается
на середине.

Доступ к шаре открывается по требованию: на время монтирования заводится
одноразовая учётная запись, а порт 445 открывается для адреса конкретного BMC
через множество с таймаутом в nftables. Окно продлевается, пока BMC
подтверждает, что образ смонтирован, и закрывается само, если сервис упадёт.

## Возможности

- Инвентарь серверов; пароли BMC шифруются Fernet.
- Библиотека образов: загрузка из браузера (возобновляемая), скачивание по
  ссылке силами сервера, SHA256. Образы больше 4.7 ГБ отсеиваются сразу —
  прошивка их не примет.
- Монтирование и отсоединение, статус слотов опрашивается у BMC.
- Однократный boot override и управление питанием.
- Ссылка на HTML5-консоль сервера.
- Именные учётные записи, argon2, CSRF, ограничение попыток входа, аудит-журнал.

## Развёртывание

Нужны Docker с compose и nftables на хосте.

```sh
git clone https://github.com/Ttolyanich/ipmi-web.git /opt/ipmi-web
cd /opt/ipmi-web
cp .env.example .env      # заполнить, ключи генерируются командами из комментариев
```

Хостовый демон, управляющий окном в файрволе (у контейнера намеренно нет
`NET_ADMIN`):

```sh
install -m 644 helper/ipmi-fw-helper.service /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now ipmi-fw-helper
```

Сам сервис:

```sh
docker compose pull && docker compose up -d
```

Панель слушает `127.0.0.1:5006` — публиковать её наружу не нужно, доступ через
nginx за VPN или по списку адресов.

Демон при первом запуске сам заводит в `table ip filter` множество
`ikvm_allow` и правило для порта 445. Ruleset хоста при этом не
перечитывается: если в `/etc/nftables.conf` стоит `flush ruleset`, его
перечитывание снесёт цепочки Docker. Чтобы правило пережило перезагрузку,
добавь его в конфигурацию файрвола руками — фрагмент в
[`nftables/ikvm.nft`](nftables/ikvm.nft).
