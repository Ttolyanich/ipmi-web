# ipmi-web

**`ipmi-web`** — веб-панель аварийного монтирования ISO-образов на серверы через BMC (IPMI / Virtual Media) без Java, без `stunnel` и без установки утилит на ПК администратора.

Вся грязная работа выполняется на сервере панели. Администратору нужен только веб-браузер — даже ночью в экстренной ситуации.

---

## 🎯 Главные возможности

- 🖥 **Интуитивный Datacenter Ops интерфейс**:
  - Полная поддержка **Тёмной и Светлой темы** (переключатель в шапке с запоминанием выбора в `localStorage`).
  - **Пошаговый мастер аварийного восстановления** на карточке сервера (`1. Выбор ISO → 2. Монтирование → 3. Однократная загрузка → 4. Перезагрузка и HTML5-консоль`).
  - Четкое отделение безопасных операций с питанием от критических (`Reset`, `Обесточить`) с подсвеченными «опасными зонами» и модальными диалогами подтверждения.
  - Честный вывод сырых текстов ошибок от BMC при сбоях связи.

- 💿 **Управление ISO-библиотекой**:
  - Чанковая возобновляемая загрузка из браузера (кусками по 8 МБ, обрыв связи не начинает загрузку заново).
  - Автономное фоновое скачивание образов по прямому URL силами сервера.
  - Автоматический подсчёт SHA256 и фильтрация образов свыше 4.7 ГБ (ограничение прошивок BMC).

- ⚡ **Управление серверами и питанием**:
  - Опрос реального состояния слотов монтирования и питания напрямую у BMC железа.
  - Назначение безопасной однократной загрузки (Boot Override: `CD-ROM`, `Disk`, `PXE`, `BIOS Setup`).
  - Прямые ссылки на встроенную HTML5-консоль BMC.

- 🔒 **Безопасность и Аудит**:
  - Именные учётные записи (роли: `администратор` / `оператор`), хеширование паролей Argon2, Fernet-шифрование паролей BMC в базе.
  - Защита от CSRF на всех формах и AJAX-запросах, rate-limiting (блокировка при 5 неудачных попытках входа).
  - Подробный именной журнал действий (аудит логирования).

## 🛠 Зачем это нужно (Проблема и Решение)

На серверах Supermicro в консоль управления ведут два пути:
1. **HTML5-консоль** — работает стабильно, но в этой платформе не умеет монтировать ISO-образы с компьютера админа.
2. **Java-виджет (`iKVM.jar`)** — умеет монтировать ISO, но регулярно ломается из-за версий JRE, политик безопасности и просроченных самоподписанных SSL-сертификатов BMC.

**`ipmi-web` решает эту проблему полностью:**
Сервис хранит библиотеку образов и раздаёт их по HTTP/SMB, а **BMC забирает образ сам** средствами своей прошивки. Java не участвует нигде, проприетарные бинарники не требуются, покупка лицензии Redfish не нужна.

## 📐 Архитектура и Порядок работы

### Схема взаимодействия
```
Администратор ──> Браузер ──> ipmi-web (Flask 5006) ──(HTTP/SMB + API)──> BMC сервера
                                    │                                           │
                                    └────── HTTP/SMB раздача ISO (read-only) <──┘
                                                 (BMC забирает образ сам)
```

### Принцип монтирования
1. Монтирование прописывается в конфигурации BMC, поэтому **переживает перезагрузки сервера** — установка ОС с её 2–3 ребутами не разваливается на середине.
2. Доступ к раздаче открывается по требованию: на время монтирования порт открывается для адреса конкретного BMC через `nftables` с автоматическим таймаутом.
3. Окно продлевается, пока BMC подтверждает активность монтирования, и автоматически закрывается при завершении или сбое.

## ⚙️ Быстрый старт и Развёртывание

### Требования
- Linux-хост с **Docker**, **Docker Compose** и **nftables**.

### 1. Клонирование и настройка окружения
```bash
git clone https://github.com/Ttolyanich/ipmi-web.git /opt/ipmi-web
cd /opt/ipmi-web
cp .env.example .env      # Заполнить секреты (ключи генерируются командами из комментариев)
```

### 2. Установка файрвол-хелпера на хост
Хостовый демон `ipmi-fw-helper` управляет временными правилами в файрволе (контейнер не имеет прав `NET_ADMIN`):
```bash
install -m 644 helper/ipmi-fw-helper.service /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now ipmi-fw-helper
```

### 3. Запуск сервиса
```bash
docker compose pull && docker compose up -d
```

Панель слушает `127.0.0.1:5006` (или `BIND_ADDR`), наружу выставляется через Nginx (готовый пример vhost с разбором строк лежит в [`deploy/nginx-ipmi-web.conf`](deploy/nginx-ipmi-web.conf)).

*(Опционально)* Добавьте правило для множества `ikvm_allow` в конфигурацию nftables хоста ([`nftables/ikvm.nft`](nftables/ikvm.nft)), чтобы правило сохранялось при перезагрузке хоста.

---

### Резервное копирование

Достаточно двух путей, и оба критичны:

```bash
tar czf ipmi-web-backup.tgz -C /opt/ipmi-web .env data/
```

`.env` содержит `FERNET_KEY` — **без него пароли BMC в базе не расшифровать
никогда**, инвентарь превратится в список адресов без доступа. `data/` — сама
база. Библиотека образов бэкапа не требует, образы качаются заново.

## ⚠️ Известные подводные камни (Грабли)

Собрано по итогам внедрения — каждая проблема стоила часов отладки:

| Симптом | Причина | Решение |
|---|---|---|
| `invalid role` при обращении к питанию | `ipmitool` выбирает набор шифров сам; если на BMC разрешён только 3-й, нужен явный `-C 3` | Задать параметр `IPMI_CIPHER_SUITE=3` в `.env` |
| Загрузка файла падает с `413` | В Nginx не задан `client_max_body_size` | Добавить `client_max_body_size 100M;` в конфиг Nginx |
| `op.cgi` отвечает `403` с пустым телом | Не передан CSRF-заголовок прошивки BMC | См. разбор в [`docs/bmc-api.md`](docs/bmc-api.md) |
| Монтирование не проходит | HTTP-режим в поле Share host прошивкой конкретного BMC не поддерживается | Переключить режим на SMB в настройках |
| Пароль к шаре не принимается | Прошивка BMC не переваривает спецсимволы | Использовать пароли только из букв и цифр |
| Правило в nftables есть, а пакетов нет | `accept` завершает обход только своей цепочки | Правило должно быть в основной цепочке хоста с `policy drop` |

- **Backend**: Python 3.12, Flask 3.0.3, Gunicorn (1 worker), Flask-SQLAlchemy, SQLite, APScheduler, Cryptography (Fernet), Argon2.
