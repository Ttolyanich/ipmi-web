# Гигиена BMC

Находки по целевому BMC (Supermicro X11DPL-i, FW 1.76) от 11.08.2026, снято
`ipmitool lan print 1`. Это не задача `ipmi-web`, но сервис будет управлять
этими BMC, и без этих правок он управляет заведомо скомпрометированными
устройствами.

Конкретные адреса, MAC и результаты сканирования намеренно **не приводятся**:
репозиторий публичный, а вместе со списком незакрытых дыр адрес живой машины
превращается в готовую инструкцию для чужого. Держи их в своих заметках.

Сеть: публичный /29 со шлюзом, маршрут наружу есть — pull-модель драйвера
реализуема.

## 1. Пароль ADMIN утекает протоколом

[CVE-2013-4786](https://nvd.nist.gov/vuln/detail/CVE-2013-4786): в IPMI 2.0
любой может запросить RAKP message 2 на 623/udp и получить HMAC от пароля
пользователя для офлайн-перебора. Дефект спецификации, патча не существует.

Единственная защита — **не выпускать 623/udp в интернет**. Пока порт открыт,
пароль этого BMC следует считать вопросом времени.

Действия: сменить пароль; закрыть 623/udp на маршрутизаторе площадки; проверить
в вебморде наличие **Configuration → IP Access Control** (есть в части прошивок
X10/X11) и ограничить доступ списком адресов.

## 2. Блокировка ADMIN как DoS с любого адреса

```
Bad Password Threshold  : 3
Invalid password disable: yes
User Lockout Interval   : 76800
```

Три неверные попытки с любого адреса отключают ADMIN на 21 час. Для аварийного
инструмента это отказ ровно в тот момент, когда он нужен.

Пока BMC доступен из интернета, лечится только ограничением доступа (пункт 1).
Крутить сам порог смысла мало: снизив защиту от перебора, упираемся обратно в
пункт 1.

## 3. SNMP community `public`

Читаемая всем информация о железе. Сменить или отключить SNMP.

## 4. ADMIN доступен без шифрования

```
RMCP+ Cipher Suites   : 1,2,3,6,7,8,11,12
Cipher Suite Priv Max : XaaaXXaaaXXaaXX
```

Suite 0 (без аутентификации вовсе) закрыт — хорошо. Но suites 1 и 2 дают ADMIN
без конфиденциальности: трафик и учётные данные идут открытым текстом. Suite 3
— HMAC-SHA1 плюс AES-CBC-128 — единственный, который стоит оставить:

```
ipmitool -I lanplus -H BMC_IP -U ADMIN -P 'ПАРОЛЬ' lan set 1 cipher_privs XXXaXXXXXXXXXXX
```

Позиции в строке соответствуют suite 0–14; `a` — разрешено для ADMIN, `X` —
suite не используется.

> **Побочный эффект, о который легко споткнуться.** После этой настройки
> `ipmitool` перестаёт работать без явного указания набора: по умолчанию он
> пробует свой (обычно 17), получает отказ и сообщает
> `Error in open session response message : invalid role` — по этому тексту
> причину не угадать. Поэтому драйвер всегда передаёт `-C 3 -L ADMINISTRATOR`;
> значение меняется переменной `IPMI_CIPHER_SUITE`.

## 5. Слабые типы аутентификации

`Auth Type Support: NONE MD2 MD5 PASSWORD` — наследие IPMI 1.5. Отключить в
вебморде всё, кроме требуемого, если прошивка позволяет.

## Возможность: сосед по /29

Маска /29 даёт шесть рабочих адресов: `.49` — шлюз, `.54` — этот BMC, остаются
четыре. Если в сегменте есть другая наша машина, Samba-шару можно поднять на
ней, и SMB-трафик не выйдет в интернет — открывать 445 наружу не понадобится,
а вместе с этим исчезает принятый риск №2 из `DECISIONS.md`.

Проверить: `nmap -sn <сеть BMC>/29`
