# Бриф на переработку интерфейса

Документ для того, кто будет делать интерфейс `ipmi-web` — человека или
ассистента. Бэкенд написан и работает; задача — заменить внешний вид, **не
сломав поведение**. Ниже: что это за инструмент, кто им пользуется, все
маршруты и данные, и список правил, нарушение которых ломает работу.

---

## 1. Что это за инструмент

Панель для монтирования установочных ISO-образов на серверы через их BMC
(контроллер управления, он же IPMI). Заменяет проприетарный Java-виджет
Supermicro, который постоянно ломался.

Сервис хранит библиотеку образов, раздаёт её по SMB, и командует BMC:
«возьми вот этот образ и покажи его серверу как USB-CD». Дальше администратор
загружает сервер с этого образа и ставит ОС.

## 2. Кто и когда им пользуется

Системные администраторы. Важно: **инструмент аварийный**. Им пользуются
редко — раз в несколько месяцев, — и почти всегда в неприятной ситуации:
сервер не грузится, надо срочно переставить или восстановить систему, часто
ночью.

Отсюда требования к интерфейсу, более важные, чем красота:

- **Понятность с нуля.** Человек не помнит, как этим пользоваться: он был тут
  полгода назад. Порядок действий должен читаться со страницы.
- **Видимое состояние.** Что сейчас смонтировано, включён ли сервер, куда он
  загрузится в следующий раз — без переходов и догадок.
- **Опасные действия отделены от безопасных.** «Reset» и «Обесточить» на
  боевом сервере необратимы. Сейчас они закрыты `confirm()`; заменять на
  что-то менее заметное нельзя.
- **Ошибки железа показываются как есть.** BMC отвечает невнятно, и текст
  ошибки — единственная зацепка. Прятать его под «что-то пошло не так» нельзя.

Правильный порядок работы, который интерфейс должен подсказывать сам:
**выбрать образ → смонтировать → назначить однократную загрузку с CD →
перезагрузить → открыть консоль**.

## 3. Технические рамки

- Сервер: **Flask + Jinja2**, страницы рендерятся на сервере. Шаблоны в
  `app/templates/`, статика в `app/static/`. Сборки фронтенда нет и заводить её
  не нужно — образ собирается без Node.
- Формы обычные, `POST` с редиректом. JSON отдают **только** ручки загрузки
  файла (раздел 6).
- Внешних CDN нет и не должно быть: сервис работает во внутренней сети, часто
  без интернета. Всё, что нужно, кладётся в `app/static/`.
- Текущая палитра — красно-чёрная, как в остальных панелях парка
  (`samba-web`, `srv-control`). Держаться её не обязательно, но узнаваемость
  парка — плюс.

## 4. Экраны

| Маршрут | Шаблон | Что показывает |
|---|---|---|
| `GET /login` | `login.html` | Вход. Единственная страница без навигации |
| `GET /servers` | `servers.html` | Список серверов, у каждого — что смонтировано |
| `GET /servers/<id>` | `server_detail.html` | **Главный экран.** Состояние, монтирование, загрузка, питание, история |
| `GET /servers/new`, `GET /servers/<id>/edit` | `server_form.html` | Карточка сервера (только администратор) |
| `GET /library/` | `library.html` | Библиотека образов, загрузка и скачивание |
| `GET /audit` | `audit.html` | Журнал действий, постранично по 100 |
| `GET /users` | `users.html` | Пользователи (только администратор) |

### Действия (все — `POST`, все требуют CSRF-токен)

| Маршрут | Поля | Смысл |
|---|---|---|
| `/login` | `username`, `password` | Вход. 5 неудач с адреса за 5 минут → блокировка |
| `/logout` | — | Выход |
| `/servers/new`, `/servers/<id>/edit` | `name`, `address`, `vendor`, `bmc_user`, `bmc_password`, `console_url`, `notes` | Пустой пароль при правке = «оставить прежний» |
| `/servers/<id>/delete` | — | Удаление, запрещено при активном монтировании |
| `/servers/<id>/mount` | `filename` | Смонтировать образ |
| `/servers/<id>/unmount` | — | Отцепить |
| `/servers/<id>/boot` | `target` = `cdrom`/`disk`/`pxe`/`bios` | Однократная загрузка |
| `/servers/<id>/power` | `action` = `on`/`off`/`reset`/`soft` | Питание |
| `/library/download` | `url`, `filename` | Скачать образ силами сервера |
| `/library/delete` | `filename` | Удалить образ |
| `/library/hash` | `filename` | Посчитать SHA256 |
| `/users/create` | `username`, `password`, `is_admin` | Создать пользователя |
| `/users/<id>/toggle` | — | Включить/отключить |
| `/users/<id>/password` | `password` | Сменить пароль |

## 5. Данные, которые приходят в шаблоны

**`server_detail.html`** — самый насыщенный экран:

- `server` — `name`, `address`, `vendor`, `console_link`, `notes`.
- `slots` — список слотов эмуляции, у каждого `index` и `mounted` (булево).
  Может быть `None`, если BMC не ответил.
- `power` — строка `on`/`off` или `None`.
- `error` — текст ошибки связи с BMC или `None`.
- `mount` — активное монтирование или `None`: `filename`, `started_by`,
  `started_at`, `last_seen_at`.
- `images` — список словарей: `filename`, `size` (байты), `sha256`
  (может быть `None`), `too_big` (булево).
- `history` — последние 10 монтирований: `filename`, `started_by`,
  `started_at`, `ended_at`, `state`, `error`.

**Фильтры Jinja:** `|bytes` — размер по-человечески, `|moment` — дата
`ДД.ММ.ГГГГ ЧЧ:ММ`. Оба возвращают `—` для пустого значения.

**Глобально доступны:** `user` (текущий пользователь: `username`, `is_admin`),
`csrf_token()` и `config`.

**Флеш-сообщения:** две категории — `ok` и `error`.

## 6. Правила, которые нельзя нарушать

Это не стилистические пожелания, а места, где ошибка ломает работу.

1. **CSRF-токен в каждой форме.**
   `<input type="hidden" name="csrf_token" value="{{ csrf_token() }}">`
   Без него сервер вернёт `400`. Для `fetch` — заголовок `X-CSRF-Token`.
2. **Возобновляемая загрузка образа.** Файлы многогигабайтные, обрыв на 90% не
   должен начинать всё заново. Протокол в `app/static/js/upload.js`:
   `POST /library/upload/init` (JSON `filename`, `size`) → цикл
   `POST /library/upload/<id>` с заголовком `X-Upload-Offset` и телом-куском →
   `POST /library/upload/<id>/finish`. Ответ `409` содержит верное смещение,
   с которого надо продолжить. Переписывать на обычный `<input type=file>`
   нельзя.
3. **Образы больше 4.7 ГБ.** Прошивка BMC их не принимает. Такие образы
   помечены `too_big` и в списке выбора должны быть **недоступны**, а не
   просто подсвечены: иначе человек узнает об ограничении посреди установки,
   по невнятной ошибке ввода-вывода.
4. **Boot override однократный.** В интерфейсе не должно появляться опции
   «сделать постоянным»: постоянный флаг заставит сервер грузиться с образа
   после установки, то есть зациклит её.
5. **Состояние слотов приходит от BMC, а не из базы.** Показывать его как
   «сейчас на железе». Если `error` не пуст — честно сказать, что состояние
   неизвестно, а не рисовать пустые слоты.
6. **`minlength` пароля берётся из `config.MIN_PASSWORD_LENGTH`**, не числом:
   иначе проверка в браузере разъедется с серверной.
7. **Подтверждение на необратимом.** Питание, удаление сервера, удаление
   образа.

## 7. Состояния, которые надо нарисовать

Их легко забыть, а встречаются они как раз в плохие моменты:

- Серверов ещё нет; библиотека пуста.
- **BMC не отвечает** — карточка сервера открывается, но состояние неизвестно.
- Образ смонтирован **мимо сервиса** (через вебморду BMC): активной записи нет,
  а слот занят. Для этого есть отдельная кнопка «отцепить».
- Идёт скачивание по ссылке: статус `pending`/`running`/`done`/`error` и
  проценты.
- Идёт загрузка из браузера: проценты, возможность продолжить после обрыва.
- SHA256 ещё не посчитан.
- Пользователь отключён.
- Вход заблокирован после неудачных попыток.

## 8. Словарь

Термины должны звучать одинаково во всём интерфейсе:

| Термин | Значение |
|---|---|
| BMC | контроллер управления сервером; живёт отдельно от ОС и работает, даже когда сервер выключен |
| Образ | ISO-файл в библиотеке |
| Монтирование | сервер видит образ как подключённый USB-привод |
| Слот | одно из трёх устройств эмуляции в BMC |
| Однократная загрузка | указание грузиться с устройства один раз |
| Окно | временно открытый доступ BMC к нашей шаре |

## 9. Чего делать не нужно

- Проксировать KVM-консоль: она работает своя, из карточки на неё ведёт ссылка.
- Показывать датчики, журналы SEL, состояние дисков — для мониторинга есть
  Zabbix.
- Придумывать JSON-API поверх существующих форм: если он понадобится, это
  отдельная задача, а не побочный эффект переделки внешнего вида.
